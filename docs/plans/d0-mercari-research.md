# D0: メルカリ取得可能性・用途調査

[国内拡張ロードマップ（D系）](domestic-expansion-roadmap.md) D0の成果物。[越境ECリサーチロードマップ](cross-border-research-roadmap.md) X0と同じ台帳形式で記録する。公式資料を確認した事実と、そこから導いた推測を分けて記載する。

調査日: 2026-09-14。対象: メルカリ（jp.mercari.com、フリマアプリ）。調査方法: 公開されている利用規約・ガイド・robots.txtの内容確認、および対象URLへの単発アクセスによる技術的な応答確認（継続的な自動取得は行っていない）。

## 記録

| 記録項目 | 内容 |
|---|---|
| 取得経路 | 一般開発者向けの公式な商品検索APIは存在しない。「Mercari Shops API」（`api.mercari-shops.com`）は法人・個人事業主が自分のショップの商品を管理するための別サービスであり、他者の出品情報を横断検索する用途のものではない。非公式のPython/JSラッパー（mercapi等、GitHub上に複数存在）はメルカリの内部API（Web/アプリが使うエンドポイント）へのリバースエンジニアリングであり、公式に許可された経路ではない。事実: 公式検索APIなし、Shops APIは対象外用途。推測: 非公式ラッパーは動作するが規約違反リスクを伴う。 |
| 価格の意味 | メルカリは定額出品制（フリマ）であり、オークションの落札価格に相当する「成立価格」フィールドが公式に公開されているわけではない。SOLD表示のある商品は最後に表示されていた出品価格が残るが、コメント欄での値下げ交渉後に出品者が価格を書き換えてから購入されるケースがあるため、表示価格が実際の取引額と一致する保証は個々の商品ごとに確認できない。事実: 定額出品制、SOLD後も直近価格の表示が残る（一般的な挙動として広く知られる）。推測: 値下げ交渉を経た成約はYahooオークション落札価格ほどの確度を持たない。 |
| 用途・保持 | 未確認。SOLD商品がいつまで検索結果・詳細ページに残るか（保持期間）を本調査では検証していない。商用表示・派生分析・CSV出力・削除要求対応の可否も未確認。 |
| 品質 | 未確認（自動取得ができないため実データでの検証は行っていない）。商品状態・カテゴリ・送料負担・発送元地域等の項目は一般に画面表示されることが知られているが、型番・版・地域仕様の照合可否はYahoo同様に出品者の自由記述に依存すると推測する。 |
| 原価と運用 | 自動取得を行う場合、内部APIへの直接アクセスまたはヘッドレスブラウザによるJSレンダリングのいずれかが必須となり、既存Yahoo実装（`Main/infrastructure/http.py`のrequests直接GET）と同じ方式は使えない（下記「技術確認」参照）。運用コスト・利用上限は経路が定まっていないため試算していない。 |
| 結論 | **限定可（自動取得は不可、手入力のみ）**。根拠は下記「規約確認」「技術確認」。証拠URLと確認日は各項に記載（2026-09-14）。再確認条件: メルカリが利用規約・ガイドを改定した場合、または公式に提携API等を提供した場合は再調査する。次の作業: D1（Mercari Provider実装）は本判定のままではADR 0005が想定する「Yahoo adapterと同一interfaceのmercari.py」（HTTP取得アダプター）を実装できないため、着手可否は別途判断する。 |

## 規約確認

- 利用規約本文（[static.jp.mercari.com/tos](https://static.jp.mercari.com/tos)、確認日2026-09-14）第8条は禁止事項をガイドへ委任している。
- ガイド「その他、不適切と判断される行為（禁止されている行為）」（[help.jp.mercari.com/guide/articles/900/](https://help.jp.mercari.com/guide/articles/900/)、確認日2026-09-14）に以下の項目が明記されている（原文引用）。
  - 「弊社が提供するインターフェイスとは別の手法を用いてサービスにアクセスすること」
  - 「弊社の事前の書面による許可なく、弊社のサービス外のところで、商業目的で、弊社が提供するあらゆるサービス、コンテンツ、情報、システム、機能、プログラムなどの全部または一部を利用すること」
  - 「弊社のウェブサイトに関連するシステムやソフトウェア、プロトコルなどをリバースエンジニアリングや逆アセンブルなどの手法により解読する行為、これらを改ざん、修正などする行為、および、これらを複製、二次利用する行為」
- 利用規約第21条第1項（[static.jp.mercari.com/tos](https://static.jp.mercari.com/tos)）は、出品者が投稿した写真・情報等を含む「本サービスを構成するすべての素材」について、ユーザーが権利者の許可なく利用してはならない旨を定める。
- robots.txt（[jp.mercari.com/robots.txt](https://jp.mercari.com/robots.txt)、確認日2026-09-14）は`/mypage/`・`/purchase/`・`/sell/`・`/transaction/`・`/v1/`・`/v2/`等をDisallowとしているが、`/search`・`/item/`自体は明示的にDisallowされていない。ただしrobots.txtの許可はToSの禁止事項を上書きしない。

事実として確認できたのは上記引用箇所そのもの。「本サービスへの自動アクセス全般を意図した条項である」という解釈は、条文からの合理的な推測であり、メルカリ側の一次的な解説・判例等では確認していない。

## 技術確認

- `https://jp.mercari.com/search?keyword=...`へ単発でHTTP GETを行い応答を確認したところ（確認日2026-09-14）、返るHTMLは検索UIの枠組みのみで、商品名・価格・SOLD表示・画像URL・件数などの実データは含まれていなかった。メルカリの検索結果はJavaScriptによるクライアントサイドレンダリングに依存しており、Yahooオークションのような「requestsで静的HTML取得→パース」（[Main/infrastructure/http.py](../../Main/infrastructure/http.py)、`ALLOWED_EXTERNAL_HOSTS = {"auctions.yahoo.co.jp"}`）の方式では商品データを取得できない。
- 構造化データを得るには (a) メルカリの内部API（Web/アプリが利用するエンドポイント）へ直接アクセスする、(b) ヘッドレスブラウザでJSを実行してレンダリング結果を取得する、のいずれかが必要になる。(a)は前述の規約上の「インターフェイス外アクセス」「リバースエンジニアリング」禁止に正面から抵触する。(b)は規約上のグレー度は(a)より低いものの、既存Yahoo実装より明確に技術的複雑さ・検知リスク・実行コストが高く、「既存Yahoo取得と同水準のリスクを超えない」という[国内拡張ロードマップ](domestic-expansion-roadmap.md)の前提を満たさない。

## 判定の整理

- **自動取得（内部APIアクセス／ヘッドレスブラウザ含む）: 不可**。規約上の複数の明示的禁止事項に該当し、技術的にも既存Yahoo実装のリスク水準を超える。
- **手入力（利用者本人が自分のブラウザ・アプリで閲覧した情報を、自分のアカウントへ意思決定支援目的で入力する行為）: 限定可**。利用者が公式インターフェイスで閲覧する行為自体は禁止事項に該当しない。ただし転記した情報の保存・表示が第21条（コンテンツの権利）との関係でどこまで許容されるかは本調査で結論を出していない。商用サービスとして提供する場合は法務確認を推奨する。
- 上記は法的助言ではなく、公開資料の読解に基づく本プロジェクトの実装方針判断である。
