# Multi-market Search and Overseas Sourcing

## Status and purpose

2026-09-03: 開発方針としてメルカリの既存機能への統合を採用。海外ECを仕入れ先候補として比較する調査を追加する。全項目は未実装であり、API利用権・本番取得・商用利用・データ品質はNOT VERIFIED。現行のYahoo機能を維持し、小さな市場別実装に分ける。

海外ECの初期調査候補はeBay。検索用Browse APIの公開仕様があるためで、利用可能性や採用を確約するものではない。他市場はM0の条件と対象カテゴリの需要を満たす場合に追加候補とする。

## User workflow and boundaries

2026-09-12: 国内仕入れ→海外販売の追加計画は[越境ECリサーチロードマップ](../plans/cross-border-research-roadmap.md)のX0〜X7で扱う。本書のM3は海外仕入れ→国内販売として維持する。取得調査・市場識別・金額/観測の制約は共有し、費用と配送方向は分ける。越境領域はSystema内に独立して設ける方針で、別Djangoアプリを含む具体配置はX1のADRで確定する。以下の既存Main内配置案を越境新領域に無条件適用しない。両計画とも機能実装済みを意味しない。

- 既存の市場検索で取得元を選択し、ターゲット分析で国内販売相場と購入候補を比較する。各行へ取得元・通貨・出品状態・更新日時・出典リンクを表示する。
- メルカリは出品中の購入候補と販売済みの相場根拠を分ける。販売済み表示だけで実際の決済価格や販売日時が確認できるとは扱わない。取得できない値は不明とする。
- 保存条件に取得市場・販売想定市場を含め、同じキーワードの別市場条件を意図せず上書きしない。既存条件はYahooを既定として維持する。
- ウォッチ→在庫→出品→販売結果へ購入元と購入時の根拠を引き継ぐ。複数市場のデータを追加しても、Yahoo限定のSellerListing公開ページ更新を他市場へ無条件に拡張しない。
- 初期は商品候補の検索・比較と外部ページへの遷移まで。自動購入/入札、自動出品、ユーザーのECパスワードやCookie保存は対象外。
- ログイン所有の保存・通知・在庫を維持し、匿名Yahoo検索の互換性を保つ。他人の検索条件・費用設定・履歴を共有しない。

## M0: Acquisition feasibility gate

市場ごとに公式API、データ提供契約、許可されたフィードなどを確認し、次を証拠URL・確認日・可否/不明・条件とともに記録する。

1. 出品中検索、販売済み価格/日時、送料/配送先、状態/型番の取得可否と鮮度。
2. 商用表示、価格比較/派生分析、キャッシュ/履歴保持期間、削除要件、CSV出力、通知利用の許容範囲。
3. 本番アクセス、認証方式、必要な申請、レート制限、費用、障害時の扱い。
4. 最小fixtureと必要項目の対応表、想定利用数での原価、取得不能時の縮退範囲。

オークファンとの連携実績はSystemaへの利用許諾ではない。一般メルカリ市場の検索と、自店の商品を扱うメルカリShops APIを混同しない。公開ページや非公式ライブラリの存在だけで取得・再利用可と判断せず、アクセス制限の回避を実装しない。

取得経路が確定しない間はconnectorを有効にしない。本人が利用可能な情報を手入力する候補URL・価格メモは代替案として評価するが、自動取得の完成扱いにしない。有料契約や対外的な申請は条件を具体化してから別途承認を得る。

## Comparable evidence and landed cost

- 市場別に件数・期間・状態・価格分布を表示する。通貨換算だけで異なる市場の中央値を混ぜない。型番、型番の地域差、状態、付属品、数量、送料込み/別を照合し、不一致・不明とユーザー除外を保持する。
- 出品価格、入札価格、販売済み表示価格、本人の確定売価は別の意味として記録する。検索結果数を市場全体の需要や販売率と解釈しない。既存予測/バックテストへ新市場を自動混入しない。
- 海外の総仕入原価は商品額、現地送料、国際送料、転送/決済手数料、関税・輸入税等の見積を含める。配送先は日本を初期想定し、日本発送可否、到着目安、返品条件を取得できる範囲で示す。
- 税・送料は取得値/手入力/推定/不明を分け、不明を0円にしない。品目に応じた税額を一律の税率で断定しない。取得条件や輸入上の制約は対象カテゴリの選定時に確認する。
- 元通貨の金額と円換算額、為替レート・適用日時・取得元/手入力の別を保持する。初期は手入力の為替・費用でも成立させ、外部為替サービスの採用は別途評価する。
- 国内想定売価から総仕入原価と国内販売費用を引き、見込み利益を算出する。目標利益から購入上限を求め、為替/送料を変えた場合の差を表示する。必要費用や配送可否が不明なら条件付き/判定不可とする。

## Planned architecture and compatibility

これは実装前の制約であり新スキーマの確定ではない。具体的なフィールドと移行はM1でAPI/DB設計を更新する。

- `Main/views/api.py`は入力検証、`Main/services/`は市場別取得の調整・所有者・保存、`Main/domain/`は商品比較・通貨/費用計算を担当する。外部I/Oと市場別解析は`Main/infrastructure/`と`Main/scraping/`へ分離する。
- 市場と外部商品IDの組合せを識別子にし、出典URL、観測日時、価格種別、通貨を正規化する。同一商品の別市場出品をURL類似だけで統合しない。
- 各取得元の機能可否を明示する。1市場の失敗で成功したYahoo結果を消さず、空結果/未対応/部分失敗/古い観測を区別する。失敗を売切れと判定しない。
- 外部取得中にDBトランザクションを保持しない。保存前に所有者を再確認し、観測と実行結果を原子的に保存する。再試行で重複登録・通知が発生しない。
- URLの許可先、timeout、応答上限、利用上限と規定に沿った再試行を市場別に定義する。外部APIの正規資格情報が必要ならサーバー側secretとして管理し、商品データ・履歴・ログへ入れない。
- 既存の円整数フィールドとAPIは意味を変えない。外貨の小数精度と丸めを別途定義し、元データを破壊的に変換しない。Yahoo既存データへの市場値の補完とロールバックを検証する。
- 保存期限/削除要求がある外部データは、それに従って履歴・CSV範囲を制限する。ユーザーの実費・販売実績と外部の参照情報を区別し、契約上保持できない資料の永久保存を前提にしない。

## Acceptance and verification

- 既存Yahoo検索、保存条件、匿名データ引継ぎ、ウォッチ、在庫、出品の回帰をfixtureで検証する。
- 異市場の同じID、型番違い、送料不明、売切れでも決済価格不明、為替欠落、外貨小数、部分障害、重複ページ、取得元停止をカバーする。
- 所有者/CSRF、再試行、snapshot整合性、秘密情報非表示と保持期限を検証する。
- UIで市場選択、根拠、読込中、空/部分失敗、古いデータ、判定不可、モバイル、再入力せず在庫へ移す動線を確認する。
- ライブ接続、本番利用資格、商用再利用、DB移行と運用は独立して検証し、fixture成功をライブ提供可能の根拠にしない。

## Public source findings (checked 2026-09-03)

- [オークファンの公式機能一覧](https://aucfan.com/dyn/member/premium/): 通知、利益計算、売上集計等を参考にする。画面やデータの複製は計画に含まない。
- [オークファンとメルカリのデータ連携発表](https://aucfan.co.jp/press/release/2024/6441/): 過去取引検索の連携実績。Systema向けの取得経路/条件は未確認。
- [メルカリShops API](https://api.mercari-shops.com/docs/index.html): productsは自店商品を対象とする。一般メルカリ横断検索の提供根拠ではない。
- [eBay Browse API](https://developer.ebay.com/api-docs/buy/api-browse.html): 出品検索の候補。販売済み履歴の取得可とは推測しない。
- [eBay Buy API要件](https://developer.ebay.com/api-docs/buy/static/buy-requirements.html)と[Developer Questionnaire](https://partnernetwork.ebay.com/page/developer-questionnaire): 本番要件の案内にはBrowseの追加承認について表現差がある。対象APIと事業用途に適用される最新条件、分析/保存の許容範囲をM0で確認する。Checkout用の要件を検索のみの機能へ無条件に適用しない。
